01 / Problem

混合栈 + 多马甲，传统定位器跟不上皮肤与流程变化。

定位器脆弱

XPath / resource-id 随皮肤与版本失效。同功能按钮颜色可完全不同。

栈在交替

冷启动、权限、原生 OTP、Passkey、WebView H5、KYC 原生页轮流出现。

包不是一套 UI

T 包是贷款壳，Y 包是日历/便签等独立 App。H5 字段 YAML 不能抄到某个马甲。

框架把测什么锁在 YAML，把怎么点交给视觉模型；控制台负责选谁跑、用哪个模型、落哪份报告。

03 / Dashboard

日常主路径：配置 → 录制生成 → 选择用例 → 视觉执行 → 报告。

配置与执行

选择视觉 Agent（可改模型、Base URL、档位），选包、选账号/OTP，再点跑。队列弹层与配置面板同步，执行的是当前选中配置，不是仓库默认包。

录制生成

步骤先在内存；填 packageId，真机或 Playwright。停止后转换落盘。0 步的页跳过；已有 YAML（如 login.yaml）必须开覆盖才会改写。

入口 npm run dashboard → 浏览器打开 http://127.0.0.1:5173（可用 DASHBOARD_PORT 改端口）

04 / Modes

按稳定性选模式 — 字段回归仍用单页。

单页 ★★★

人已停在目标页。例：npm run test:basic-info。控制台对应 B 面单页。

分段 ★★

已登录后串一段，如 KYC 五步 test:kyc-full。提交只等离开当前页。

全流程 ★

冷启 pm clear → 协议 → 登录 → 分流。控制台指定 Android 包；skipLaunch / SKIP_CLEAR_DATA 可不清。

环境：ACCOUNT_PROFILE · TEST_MOBILE / TEST_OTP · SKIP_BOOTSTRAP=1 · SKIP_LOGIN=1 — 明文只放 .env

B 面 · 统一 H5 借款模版

flows + data

登录后 WebView：Basic info、联系人、KYC、Bank、Apply、Repay。不要为某个马甲去改这套字段 YAML。

  • 10 页注册于 config/pages.yaml
  • 步骤在 data/*.yaml，编排在 config/flows.yaml
  • 入口 tests/*.test.ts 与控制台「B 面」
A 面 · T 贷款壳 / Y 独立 App

05 / Hard-won

实机跑通后写进 YAML 的规则，不是「放宽断言」。

协议跟文案，不跟颜色

Agree & Continue 只在 bootstrap。皮肤可黄可蓝，locate 忽略颜色。login.yaml 不再找这一步。

Passkey 可跳过

登录后点 Skip for now。等 H5 首页时每一轮继续 dismiss，避免卡在系统弹层。

KYC 提交只等离页

五步 Submit 后 waitForKycLeavePage。活体完成后可能已是 Bank information，不假定固定下一页。

L3 不是 PRD

test:l3:explore 是有界探索冒烟。按 PRD 逐条验收走 A 面 aside 或 B 面 YAML，并先看失败截图再改 prompt。

Token / 免费额度耗尽则停止重试，不当成脚本缺陷去改 YAML。

06 / Quick Start

从控制台接真机开始 — 单页回归仍然最稳。

  1. npm install；录制用浏览器时再 npm run playwright:install
  2. 配置 .env（视觉模型 API；可选账号 / OTP，勿提交）
  3. USB 调试，adb devices 为 device，被测 App 已安装
  4. npm run dashboard，打开本机 5173 端口，选 Agent 与用例后执行
  5. 字段回归：先手动停在目标页，再跑单页（如 Basic info）
# 对照命令（控制台能做的，这些也能做）
npm run test:basic-info
npm run test:kyc-full
npm run test:business-auto
npm run test:aside:t57
npm run test:l3:explore

记住一句话：YAML 描述测什么，控制台决定谁跑，AI 负责怎么点，报告证明测过了。

产物在 midscene_run/（report · screenshots · log · cache）。密钥与 agents.local.yaml 不入库。
